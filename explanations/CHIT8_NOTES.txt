
CHIT 8 – ACCOUNTS TABLE + TRANSACTIONS (Balanced Version)

1) CONCEPT / PURPOSE:
This program demonstrates how financial transactions are safely handled in databases.
It shows:
- START TRANSACTION, COMMIT, ROLLBACK
- SAVEPOINT and ROLLBACK TO SAVEPOINT
- Stored procedure that checks balance before transferring money

Used in real banking systems to prevent data loss or wrong money movement.

2) ALGORITHM (STEP-BY-STEP):
1. Create Accounts table.
2. Insert initial balances.
3. Start a transaction to transfer amount.
4. Use ROLLBACK to undo transfer.
5. Repeat transfer and use COMMIT to confirm it.
6. Use SAVEPOINT to undo part of a transaction.
7. Stored procedure checks if balance is enough before transfer.

3) HANDWRITTEN NOTES SUMMARY:
- Transaction = Group of SQL statements executed together.
- COMMIT = Save permanently.
- ROLLBACK = Undo completely.
- SAVEPOINT = Undo from a specific point.
- Stored procedure automates operation and ensures safety.

4) DIAGRAM (DRAW IN EXAM):

Before Transfer:
1001: 20000
1002: 15000

Transfer 5000
After Commit:
1001: 15000
1002: 20000

If ROLLBACK → values return to original.

5) CODE EXPLANATION:

START TRANSACTION;
→ Begin unit of work.

UPDATE Accounts SET balance = balance - 5000 WHERE acc_no = 1001;
UPDATE Accounts SET balance = balance + 5000 WHERE acc_no = 1002;
→ Transfer 5000.

ROLLBACK;
→ Undo the transfer (no effect stays).

COMMIT;
→ Permanently apply the transfer.

SAVEPOINT sp1;
→ Mark rollback checkpoint.

ROLLBACK TO SAVEPOINT sp1;
→ Undo only the last part of the transaction.

Stored Procedure:
SELECT balance INTO v_bal...
→ Fetch current balance of sender.

IF v_bal < p_amt THEN SIGNAL...
→ Stop transfer if not enough balance.

UPDATE ... COMMIT;
→ Execute safe transfer when allowed.

6) WHY EACH COMMAND IS USED:
START TRANSACTION → Ensures atomic execution.
ROLLBACK → Avoids mistakes & protects data.
COMMIT → Confirms final values.
SAVEPOINT → Supports partial undo.
SIGNAL → Stops invalid transfers.

7) VIVA QUESTIONS:
Q: Why transactions are needed?
A: To ensure accuracy and prevent partial updates.
Q: Difference between ROLLBACK and COMMIT?
A: ROLLBACK undoes changes, COMMIT saves them.
Q: Why check balance first?
A: To avoid negative account values.

8) MODIFICATION EXAMPLE:
CALL transfer_amount(1003, 1005, 2000);

9) FINAL SUMMARY:
This chit shows how to manage safe bank transactions.
ROLLBACK, COMMIT, and SAVEPOINT ensure correct and secure balance updates.
