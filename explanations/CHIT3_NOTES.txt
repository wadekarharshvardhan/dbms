
CHIT 3 – EMP & DEPT DATABASE NOTES (Balanced Version)

1) CONCEPT / PURPOSE:
This program creates a simple company structure where:
- Departments are stored in Dept table.
- Employees are stored in Emp table.
- Each employee belongs to one department (Foreign Key).
This demonstrates:
- Table creation with constraints
- Primary & Foreign Key relationships
- Inserting records
- Creating an index for faster name search
- Using JOIN to connect employees with their departments
- Aggregation (COUNT, SUM) to report department-level information
- Updating records (salary raise)

2) ALGORITHM (STEP-BY-STEP):
1. Drop existing tables if any exist.
2. Create Dept table to store department details.
3. Create Emp table to store employee details with salary and department reference.
4. Insert few Department records.
5. Insert few Employee records.
6. Create an index on empName to improve search performance.
7. Retrieve employee count and total salary per department using JOIN and GROUP BY.
8. Create a view to display employee details along with department info.
9. Update salaries for employees in a particular department (IT).

3) HANDWRITTEN NOTES SUMMARY:
- Dept(deptId) is Primary Key.
- Emp(empId) is Primary Key.
- empDeptId is Foreign Key → Links Emp to Dept.
- CHECK(empSal >= 0) ensures salary cannot be negative.
- Index on empName improves lookup performance.
- GROUP BY is used for department-level summary.
- View (v_emp_dept) simplifies reporting.

6) WHY EACH FUNCTION IS USED:
PRIMARY KEY → uniquely identifies each record.
FOREIGN KEY → ensures employees must belong to a valid department.
CHECK(empSal >= 0) → prevents incorrect salary entry.
INDEX(empName) → speeds up searching by employee name.
GROUP BY → used to calculate department-wise totals.
VIEW → makes data reading easier and prevents complex repeated JOINs.

7) COMMON VIVA QUESTIONS:
Q: Why is Foreign Key used?
A: To maintain relationship between employee and department.
Q: Why use CHECK constraint on salary?
A: To prevent invalid negative salary values.
Q: What does index do?
A: It speeds up searching for employee names.
Q: Why create a view?
A: To simplify repeated JOIN queries.
Q: Why GROUP BY in the query?
A: To show report department-wise.
